# ManagerHub — 27-module implementation and acceptance ledger

**2026-11-25 — P0 Complete Offline FM2013 Save Decoder (Issue #114):** Implemented a verified read-only offline `.fm` save decoder (`@managerhub/domain/fm2013-offline`) and unified save-backed UI across Save Library, Player Lab, Squad Planner, Tactical Lab, and Overview with zero CSV/HTML/FMRTE/running-FM prerequisite. The decoder parses AFE/FMF v5 containers (both compressed zlib and uncompressed variants), decrypts per-member 40-byte AES-128-CTR envelopes via Web Crypto, extracts `save_game_summary.dat`, `humans.dat`, and all 51 sequential tables + post-table tail + 64-byte hash of `game_db.dat` (`0x757`–`0x774`) with strict exact-EOF verification (`remaining === 0`). Private local validation passed **65/65 real FM2013 `.fm` saves** across 7 `game_db` versions and **100.000% ground-truth cross-validation** on 4,058 live players (`198,842/198,842` attributes, `60,870/60,870` positional ratings, exact CA/PA/contracts/personality/club finances) with Football Manager closed and original `.fm` SHA-256 unchanged. Browser execution runs in a bounded cancellable Web Worker (`save-decode.worker.ts`) with opt-in local IndexedDB persistence (`managerhub-save-db` v1, never storing raw `.fm` bytes, preserving `managerhub-local` v4), strict Realism vs Editor field isolation, multi-save isolation, and VI/EN localization. Honest limitations remain explicitly labeled: `writeCapability` is `false` (`Unsupported`), unedited Stadium/Competition/City base names reside in external `lang_db.dat` (`nameProvenance: 'not_stored_in_save'`), native tactics/match-event binary members are not decoded, and compatibility applies strictly to verified FM2013 `13.3`/`13.3.3` profiles. See [offline decoder research](../research/fmrte/25-fm2013-offline-save-decoder.md). MH-01, MH-02, and MH-05 advance significantly while remaining **In progress** pending full multi-edition/corpus closure and post-merge release acceptance.

## How to update
Per module record:
- status: Not implemented / In progress / Needs verification / Complete / Blocked by compatibility;
- commit/PR and exact code paths;
- supported editions/builds and coverage;
- business rules, input/output contracts and missing-state UI;
- test commands, result IDs, browser screenshots if visual, security/a11y review;
- source of model/metrics and known limits;
- quality reviewer and date.

A format-specific capability may be **Blocked by compatibility** even while other functionality is completed. **Blocked must never be mislabeled Complete**. Full release requires a truthful capability matrix and tested coverage, not claims that every FM binary format is editable.
